Scale to Zero with the Custom Metrics Autoscaler

Step 3 lets CMA poll the waker directly. Many platform teams prefer every scaling signal to go through cluster monitoring, where it is stored, graphed and alerted on. This optional step swaps the trigger for a prometheus trigger that reads minecraft_desired_replicas from the OpenShift User Workload Monitoring stack through Thanos Querier. Behaviour does not change; only the path of the metric does.

Prerequisites

  • Step 3 completed

  • User Workload Monitoring enabled on the cluster (cluster admin)

  • Rights to grant the cluster-monitoring-view cluster role

How It Works

  1. A ServiceMonitor tells Prometheus to scrape the waker’s /metrics every 15 s.

  2. A ServiceAccount with cluster-monitoring-view gets a token; the token and the cluster CA go into the Secret keda-prometheus-token.

  3. A TriggerAuthentication hands token and CA to KEDA.

  4. The new ScaledObject queries max(minecraft_desired_replicas{namespace="$NAMESPACE", service="mc-ragnarok-waker"}) on Thanos Querier. It has the same name as the Step 3 one, so applying it replaces it.

Steps to Apply

1. Create the credentials for KEDA

What: Run scripts/setup-trigger-auth.sh to create the ServiceAccount, role binding and token Secret.

Why: Thanos Querier requires an authenticated bearer token; the metrics-api trigger needed nothing.

The script uses the current oc context, not --context. Switch to it first. 
oc config use-context cma
./scripts/setup-trigger-auth.sh "$NAMESPACE"
Verify: the Secret exists 
oc get secret keda-prometheus-token -n "$NAMESPACE" --context cma
NAME                    TYPE     DATA   AGE
keda-prometheus-token   Opaque   2      10s

2. Scrape the waker

~30 seconds (estimate: first scrapes after the ServiceMonitor is picked up)

What: Apply the ServiceMonitor for the waker.

Why: Without it the metric never reaches Prometheus and the trigger would only see empty results.

envsubst '$NAMESPACE' < manifests/waker/servicemonitor.yaml | oc apply -n "$NAMESPACE" --context cma -f -
Verify: the metric is queryable

In the web console, open Observe > Metrics, select the $NAMESPACE project and run:

minecraft_desired_replicas

One series, value 0 or 1.

3. Swap the trigger

What: Apply the Prometheus ScaledObject and its TriggerAuthentication.

Why: This replaces the metrics-api trigger in place; the Deployment keeps its current replica count.

envsubst '$NAMESPACE' < manifests/keda/scaledobject-prometheus.yaml | oc apply -n "$NAMESPACE" --context cma -f -
Verify: the ScaledObject now uses the prometheus trigger 
oc get scaledobject mc-ragnarok -n "$NAMESPACE" --context cma -o jsonpath='{.spec.triggers[0].type}{"\n"}'
oc get scaledobject mc-ragnarok -n "$NAMESPACE" --context cma
prometheus
NAME          SCALETARGETKIND      SCALETARGETNAME   MIN   MAX   READY   ACTIVE   ...
mc-ragnarok   apps/v1.Deployment   mc-ragnarok       0     1     True    False    ...

Repeat Step 4: the demo behaves the same.

What This Solves (Compared to Step 3)

Problem from Step 3 How This Step Solves It

The scaling signal is invisible to cluster monitoring

The metric is stored in Prometheus, so it can be graphed and alerted on

What This Does NOT Solve (Yet)

Remaining Problem Addressed In

A one-year token in a Secret must be rotated

Outside the workshop: rotate it, or use a shorter --duration

Alternatives Considered

Approach Notes

prometheus trigger through Thanos Querier (this step)

Signal stored and visible; needs credentials and adds one scrape interval of delay

metrics-api trigger (Step 3)

Simplest and fastest; the signal is not recorded anywhere

Reset

Put the metrics-api trigger back first, so the server is never without a ScaledObject, then remove the monitoring pieces.

envsubst '$NAMESPACE' < manifests/keda/scaledobject-metricsapi.yaml | oc apply -n "$NAMESPACE" --context cma -f -
oc delete triggerauthentication keda-prometheus-uwm -n "$NAMESPACE" --context cma --ignore-not-found
oc delete -f manifests/waker/servicemonitor.yaml -n "$NAMESPACE" --context cma --ignore-not-found
oc delete secret keda-prometheus-token -n "$NAMESPACE" --context cma --ignore-not-found
oc adm policy remove-cluster-role-from-user cluster-monitoring-view -z thanos-reader -n "$NAMESPACE" --context cma
oc delete sa thanos-reader -n "$NAMESPACE" --context cma --ignore-not-found
